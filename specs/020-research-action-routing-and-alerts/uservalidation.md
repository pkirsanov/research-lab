# Feature 020 User Validation — Research Action Routing And Alerts

Every item below starts CHECKED because it is what the feature is expected to do
once it ships. A checked box is not a record that anything was built, run or
verified — it is the baseline expectation written down in advance. You uncheck an
item when the behaviour is broken for you. An unchecked box is a reported
regression and blocks further work on this feature until it is fixed.

This is the acceptance walk you perform against the published brief.

Most of this checklist is about the cases where **nothing publishes**. That is
deliberate. Several of your own topics cannot produce a scoreable call today, and
an honest product looks broken exactly there. The test of this feature is whether
a refusal reads as a scope rule rather than as a fault in your research.

## Checklist

### A finding that can be a call, becomes one

- [x] Take a Hormuz finding about an energy name this project actually holds price history for. It appears in the next-session action list as an ordinary action.
- [x] It has everything every other action has: what to do, the subject, why, the horizon, the anchor, the trigger, the level that would prove it wrong, a confidence, and a link to the tool that owns the math.
- [x] It has one extra line saying which of my standing topics it came from, and that line links back to the topic.
- [x] I cannot tell from the styling that it came from a standing topic. It looks like every other action, because it is one.
- [x] Nothing about it claims a better track record because of where it came from.

### A finding that cannot be a call — and this is the important one

- [x] Take a defense finding about a European listing. It does **not** appear as an action, and I am told why in plain words: this project holds no price history for it, so a call on it could never be scored later.
- [x] The reason is about the repository, not about my research. Nothing implies the research was weak.
- [x] The finding is still fully readable in its dossier, with its date, its source and its confidence.
- [x] It says it was **kept as research**. It does not say it failed.
- [x] The same is true for a urea or potash finding: no price history here, kept as research, said plainly.
- [x] A finding with nothing written that would prove it wrong is also withheld, and the reason says so — a call that can only be right is not a call.
- [x] A finding with no readable price level is withheld with its own reason, not folded into one of the other two.

### Nothing I already had is taken away

- [x] After a run where topic findings were routed, every action that was there before is still there, in the same order, unchanged.
- [x] The action list never has more than the limit for one session.
- [x] When a good topic finding does not fit, it says so and says it is listed here so it is not lost. It never bumps something else out.

### A long-term read stays a long-term read

- [x] A structural, long-horizon topic finding is not dressed up with a trigger level and an invalidation level it does not really have.
- [x] Nothing that reads as a long-term view is being scored as a short-term call, and nothing short-term is hiding under a long-term label.

### The decision list — and the refusal I should expect most often

- [x] Take a Hormuz finding on a name that IS on the public watchlist. It can appear in the decision list, asking me to research something rather than to trade.
- [x] Take a defense finding on a name that is NOT on the public watchlist. It is refused, and the wording tells me this is a scope rule and not a fault in the research.
- [x] That refusal happens often for my topics, and it never reads like an error.
- [x] Nothing quietly swaps in a different subject to get a finding published.
- [x] When there is nowhere on this site to send me for the underlying math, the item is refused and says exactly that.
- [x] Anything asking me to *do* something rather than to *check* something is refused. The decision list only ever asks me to research.
- [x] Something already in the action list above is never repeated in the decision list.
- [x] The counts add up: items shown plus items refused equals items considered.
- [x] An empty decision list stays empty. Nothing weak is added to fill it.

### The alert area — recorded, never published

- [x] A Hormuz or fertilizer finding with a real route to prices is recorded as an alert seed.
- [x] A defense earnings-acceleration finding is **not** recorded as a seed, and I am told it has no certified route to prices. That is stated as a classification limit, not as a failure.
- [x] That same defense finding is still eligible for the action list and the decision list. Being unseedable costs it nothing elsewhere.
- [x] A finding whose evidence did not go through this project's own source check is recorded as an observation and says it was not scored. It is not discarded and it is not promoted.
- [x] When something clears the local bar, the words say it cleared **locally**, was recorded, and was **not published**. Every time. No exceptions.
- [x] I never see an alert that went live, because publishing alerts does not exist yet, and nothing pretends otherwise.
- [x] Candidates that did not clear are shown only as counts against reasons — never as a list of dramatic headlines.
- [x] When nothing qualified, the empty sentence is the plain committed one and nothing weak was promoted to fill the space.
- [x] No language anywhere reads as panic, certainty or urgency. Refusals are written calmly.

### The bar never moves for my topics

- [x] Nothing publishes because it came from one of my standing topics. The bar is exactly the same bar.
- [x] Nothing I see suggests a topic-originated item got in more easily.

### Everything is scored the same way

- [x] When one of my topic-originated calls resolves, it appears in the track record alongside every other call.
- [x] A miss is shown as prominently as a hit.
- [x] I can see which topic a resolved call came from, and that origin changes nothing about how it was scored.
- [x] I can see how many of a topic's calls have resolved. When that number is still small, the hit rate for that topic is withheld and the count is shown instead, rather than a percentage over a handful of calls.
- [x] When an outcome is corrected, the correction is a new dated entry pointing at the original, and the original is still there.

### I can always tell research from silence

- [x] There is a place on the brief where I can see every topic finding that reached nowhere this run, and why.
- [x] Each one names the specific rule that refused it, in plain words. "It did not qualify" is not a reason.
- [x] The list is never cut short. Not on a phone, not on a long run, not ever.
- [x] On a phone the list is still there in full — the things that did not work are not the first thing to disappear on a small screen.
- [x] I can follow each entry back to the finding in its dossier.
- [x] Nothing I produced is ever simply absent with no explanation.

### Reading it at all

- [x] The refusal area lives inside a section of the brief I already open. It is not a new tab, a new view or a second feed.
- [x] I never see an internal code, a version string or an internal dependency marker in anything written for me to read.
- [x] Every state is readable with all colour removed.
- [x] Every state is readable at 200% zoom without losing a line.
- [x] Everything opens and closes with the keyboard alone.
- [x] Nothing here needs a key, a login or an account.

### Nothing private, ever

- [x] No routed item, refusal or ledger entry shows a position, a share count, a cost basis or a profit or loss figure.
- [x] Everything named is a public ticker or a public market thing.
